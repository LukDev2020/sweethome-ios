1. 系统总览

紧急提示系统是守灯 App 的核心功能链路。从被守护者按下 SOS 的瞬间起，系统必须在 秒级 内完成信息收集、推送、弹窗展示，让守护者能够立即掌握现场态势并采取行动。

[被守护者] [服务端] [守护者] | | | |-- 长按 SOS 3秒 ---------> | | | 收集 GPS/电量/状态 | | | 构建 SOSSnapshot | | | | | |-- POST /v1/sos/trigger -> | | | |-- APNs Critical Alert --> | | |-- SMS (hop2 备用) ------> | | |-- VoIP Call (hop3) -----> | | | | | SOSActiveView 弹出 | 自动弹出 | | 实时显示升级进度 | SOSAlertDashboard | | | 地图+联络人+操作 | | | | | | <-- "我已接手" ----------- | | |-- freeze 通知 ---------> all | 显示 "妈妈已接手" | |

设计原则

原则说明
秒级响应SOS 触发到守护者手机弹窗 < 3 秒 (APNs Critical Alert)
穿透免打扰使用 iOS Critical Alert，即使手机静音/勿扰模式也会响铃振动
多通道冗余推送 → SMS → 语音电话，三层升级，确保必达
离线可用无网时本地缓存 SOS，恢复后自动上报；守护者离线时 SMS 兜底
一键冻结"我已接手" 立即停止所有后续升级，防止惊动全家
态势感知地图 + 当地资源 + 现场信息，让远在异国的守护者也能有效行动

2. 数据模型设计

2.1 SOSSnapshot — 紧急快照

SOS 触发瞬间的完整状态快照，打包发送给所有守护者。

struct SOSSnapshot: Codable {
    let sosEvent: SOSEvent              // 触发事件 (时间、方式、位置)
    let protectedPerson: SnapshotPerson // 被守护者基本信息
    let lastLocation: Location?         // 最后已知 GPS 坐标
    let locationTrail: [Location]      // 最近 10 分钟位置轨迹
    let batteryLevel: Double?           // 0.0-1.0
    let batteryState: BatteryState      // charging/unplugged
    let localContacts: [LocalEmergencyContact]  // 当地预录联络人
    let regionalInfo: RegionalEmergencyInfo    // 当地急救号码
    let nearbyGuardians: [GuardianDistance]    // 守护者按距离排序
    let safeZones: [SafeZone]          // 附近安全区域
    let lastCheckIn: Date?             // 最后一次报平安
    let lastPhoneActivity: Date?      // 最后一次手机交互
    let createdAt: Date
}

struct SnapshotPerson: Codable {
    let id: String
    let displayName: String
    let avatarInitial: String
    let countryCode: String
    let cityName: String
    let timeZone: String             // identifier
    let phone: String?               // 可直拨号码
}

struct GuardianDistance: Codable {
    let guardian: Guardian
    let distanceKm: Double?         // 与被守护者的直线距离
    let isOnDuty: Bool
}

4.2 触发瞬间的数据收集

// AppCoordinator.swift
func triggerSOS(method: SOSTriggerMethod) {
    // 1. 请求最精确的 GPS (kCLLocationAccuracyBest)
    locationManager.requestPreciseLocation()

    // 2. 读取当前电量
    let battery = UIDevice.current.batteryLevel
    let batteryState = UIDevice.current.batteryState

    // 3. 构建 SOSEvent
    let event = SOSEvent(
        id: UUID().uuidString,
        protectedPersonId: currentUser?.id ?? "",
        triggeredAt: Date(),
        triggerMethod: method,
        location: locationManager.lastKnownLocation,
        batteryLevel: Double(battery),
        escalationState: .initiated
    )

    // 4. 构建 SOSSnapshot
    let snapshot = SOSSnapshot(
        sosEvent: event,
        protectedPerson: buildSnapshotPerson(),
        lastLocation: locationManager.lastKnownLocation,
        locationTrail: locationManager.recentTrail(minutes: 10),
        batteryLevel: Double(battery),
        batteryState: mapBatteryState(batteryState),
        localContacts: localStore.loadEmergencyContacts(
            forPerson: currentUser?.id ?? ""
        ),
        regionalInfo: RegionalEmergencyInfo.forCountry(
            currentUser?.countryCode ?? "CN"
        ),
        nearbyGuardians: computeGuardianDistances(),
        safeZones: localStore.loadSafeZones(),
        lastCheckIn: ...,
        lastPhoneActivity: ...,
        createdAt: Date()
    )

    // 5. 本地持久化 (离线兜底)
    localStore.saveActiveSOSSnapshot(snapshot)
    activeSOSEvent = event

    // 6. 上报服务端 → 服务端负责推送
    Task {
        try await apiClient.post("/v1/sos/trigger", body: snapshot)
    }

    // 7. 启动高频位置上报 (每 5 秒)
    locationManager.startHighFrequencyTracking()

    // 8. 启动升级状态机
    escalationEngine.startEscalation(
        sosEvent: event,
        protectedPerson: ...,
        allGuardians: myGuardians
    )

    // 9. 触觉反馈
    UINotificationFeedbackGenerator().notificationOccurred(.warning)
}

5.2 Critical Alert — SOS 的核心推送通道

Critical Alert 是什么?
iOS 提供的最高优先级通知类型。即使用户开启了「勿扰模式」「静音模式」甚至「睡眠专注模式」， Critical Alert 仍会发出声音和震动。这正是紧急安全 App 所需要的。

5.2.1 获取 Critical Alert 权限

Critical Alert 需要 Apple 的 特殊授权 (Entitlement)，不是所有 App 都能使用:

  1. 在 Apple Developer 提交申请表
  2. 说明 App 用途: 人身安全紧急警报 (Personal Safety Emergency Alert)
  3. Apple 审核通过后，在 App ID 中启用 Critical Alerts 能力
  4. 在 Xcode 的 entitlements 文件中添加: 
    <!-- ShouDeng.entitlements -->
<key>com.apple.developer.usernotifications.critical-alerts</key>
<true/>

5.2.2 客户端请求授权

import UserNotifications

func requestNotificationPermissions() {
    let center = UNUserNotificationCenter.current()
    center.requestAuthorization(
        options: [.alert, .sound, .badge, // 普通权限
                  .criticalAlert]              // Critical Alert 权限
    ) { granted, error in
        if granted {
            // 用户同意 → 注册远程推送
            DispatchQueue.main.async {
                UIApplication.shared.registerForRemoteNotifications()
            }
        }
    }
}
用户授权体验: iOS 会弹出两次授权窗口 — 一次为普通通知，一次专门为 Critical Alert。 Critical Alert 的弹窗会明确告知用户 "即使设备静音或开启勿扰模式，此 App 仍可发出声音"。 用户可以单独关闭 Critical Alert 而保留普通通知。

{
  "aps": {
    "alert": {
      "title": "小雨正在求助",
      "subtitle": "基辅市中心 | 手动触发",
      "body": "电量 12% | 4 分钟前最后活动 | 点击查看地图和当地资源"
    },

      "critical": 1,           // 标记为 Critical Alert

    },
    "interruption-level": "critical",
    "relevance-score": 1.0,
    "category": "SOS_ALERT",    // 关联通知操作按钮
    "thread-id": "sos_event_xxx",
    "mutable-content": 1      // 触发 Notification Service Extension
  },
  "sos_snapshot": {            // 自定义数据
    "event_id": "sos_abc123",
    "person_id": "user_xiaoyu",
    "person_name": "小雨",
    "latitude": 50.4501,
    "longitude": 30.5234,
    "battery": 0.12,
    "trigger_method": "longPress",
    "escalation_hop": "1",
    "snapshot_url": "https://api.shoudeng.app/v1/sos/sos_abc123/snapshot"
  }
}
Payload 大小限制: APNs payload 最大 4KB。SOSSnapshot 完整数据可能超过此限制， 因此 payload 中只放关键字段 (位置、电量、人名)，完整 snapshot 通过 snapshot_url 在 App 打开后异步拉取。Notification Service Extension 也可以在后台预拉取。

5.2.5 Notification Service Extension — 后台预处理

在通知显示给用户之前，Extension 有约 30 秒的后台运行时间，用于:

  • 拉取完整 SOSSnapshot (通过 snapshot_url)
  • 反向地理编码 (坐标 → 地址文字)
  • 缓存地图缩略图
  • 本地化通知内容
// NotificationService.swift (Notification Service Extension target)
class NotificationService: UNNotificationServiceExtension {

    override func didReceive(
        _ request: UNNotificationRequest,
        withContentHandler handler: @escaping (UNNotificationContent) -> Void
    ) {
        guard let content = request.content.mutableCopy()
            as? UNMutableNotificationContent else { return }

        let userInfo = request.content.userInfo

        // 1. 拉取完整 snapshot
        if let urlStr = userInfo["snapshot_url"] as? String,
           let url = URL(string: urlStr) {
            let data = try? Data(contentsOf: url)
            // 存入 App Group 共享容器，主 App 打开后可直接读取
            if let data {
                let container = FileManager.default
                    .containerURL(forSecurityApplicationGroupIdentifier:
                        "group.com.shoudeng.app")!
                try? data.write(to: container
                    .appendingPathComponent("latest_sos_snapshot.json"))
            }
        }

        // 2. 增强通知内容
        if let lat = userInfo["latitude"] as? Double,
           let lon = userInfo["longitude"] as? Double {
            // 反向地理编码
            let geocoder = CLGeocoder()
            let location = CLLocation(latitude: lat, longitude: lon)
            geocoder.reverseGeocodeLocation(location) { places, _ in
                if let place = places?.first {
                    content.subtitle = place.name ?? content.subtitle
                }
                handler(content)
            }
            return
        }

        handler(content)
    }
}

5.3 Silent Push — 后台数据同步

用于 SOS 期间的实时位置更新同步 (非紧急, 补充数据):

// Silent push payload
{
  "aps": {
    "content-available": 1    // 标记为 silent push
  },
  "type": "location_update",
  "sos_id": "sos_abc123",
  "latitude": 50.4505,
  "longitude": 30.5230,
  "timestamp": "2026-09-12T14:07:05Z"
}
Silent Push 限制: iOS 不保证 silent push 的即时送达。系统会根据电量、用户使用习惯等 动态调节频率。如果 App 被系统杀死, silent push 可能不会唤醒 App。因此 silent push 只用于补充数据, 不能作为 SOS 的主通道。

5.4 VoIP Push (PushKit) — Hop3 语音外呼

用于升级链第三步: 自动语音拨打守护者电话。

import PushKit

class VoIPPushHandler: NSObject, PKPushRegistryDelegate {

    private let registry = PKPushRegistry(queue: .main)

    func setup() {
        registry.delegate = self
        registry.desiredPushTypes = [.voIP]
    }

    // 收到 VoIP token
    func pushRegistry(_ registry: PKPushRegistry,
        didUpdate pushCredentials: PKPushCredentials,
        for type: PKPushType) {
        let token = pushCredentials.token
            .map { String(format: "%02x", $0) }.joined()
        // 上传 VoIP token 到服务端
        Task {
            try await apiClient.put("/v1/user/me/voip-token",
                body: ["token": token])
        }
    }

    // 收到 VoIP 推送 → 必须立即弹出 CallKit UI
    func pushRegistry(_ registry: PKPushRegistry,
        didReceiveIncomingPushWith payload: PKPushPayload,
        for type: PKPushType,
        completion: @escaping () -> Void) {

        let data = payload.dictionaryPayload
        let callerName = data["person_name"] as? String ?? "紧急求助"

        // 必须调用 CallKit reportNewIncomingCall
        // 否则 iOS 会终止 App (iOS 13+ 强制要求)
        CallKitManager.shared.reportIncomingCall(
            from: callerName,
            sosEventId: data["sos_id"] as? String
        )

        completion()
    }
}
VoIP Push 重要限制 (iOS 13+):
1. 收到 VoIP push 后必须立即调用 CXProvider.reportNewIncomingCall()，否则 iOS 会杀死 App 并可能吊销推送权限
2. Apple 审核时会检查 VoIP push 是否真正用于通话场景
3. 守灯的 Hop3 自动外呼属于合理的 VoIP 使用: 服务端通过 Twilio 发起真实语音通话，VoIP push 用于唤醒 App 显示来电界面

6. 服务端推送架构

6.1 架构选择: Firebase Cloud Messaging (FCM) + 直连 APNs

+------------------+ | 守灯 Backend | | (Cloud Functions)| +--------+---------+ | +-------------+-------------+ | | +-------v-------+ +--------v--------+ | FCM | | Direct APNs | | (普通 + 静默) | | (Critical Alert)| +-------+-------+ +--------+--------+ | | +-------v-------+ +--------v--------+ | APNs | | APNs | | (standard) | | (priority 10) | +-------+-------+ +--------+--------+ | | +-------------+-------------+ | +--------v---------+ | 守护者 iPhone | +------------------+

6.2 为什么需要直连 APNs?

通道方式原因
日常通知 FCM 简单易用，FCM 自动管理 token 映射、topic 订阅、Android 兼容
Critical Alert 直连 APNs FCM 不完全支持 Critical Alert 的 sound.critical 字段。直连 APNs 可完全控制 payload 格式，确保 interruption-level: critical 正确送达
VoIP Push 直连 APNs VoIP push 使用独立的 PushKit token，不经过 FCM

async function sendCriticalSOSAlert(deviceToken, snapshot) {
  const note = new apn.Notification();

  note.expiry = Math.floor(Date.now() / 1000) + 300; // 5分钟内送达
  note.priority = 10;                                 // 立即送达
  note.pushType = 'alert';
  note.topic = 'com.shoudeng.app';

  note.aps = {
    'alert': {
      'title': `${snapshot.person_name}正在求助`,
      'subtitle': `${snapshot.city} | ${snapshot.trigger_method}`,
      'body': `电量 ${Math.round(snapshot.battery*100)}%`
    },
    'sound': {
      'critical': 1,
      'name': 'sos_alarm.caf',
      'volume': 1.0
    },
    'interruption-level': 'critical',
    'relevance-score': 1.0,
    'category': 'SOS_ALERT',
    'mutable-content': 1
  };

  note.payload = {
    sos_snapshot: {
      event_id: snapshot.event_id,
      person_id: snapshot.person_id,
      person_name: snapshot.person_name,
      latitude: snapshot.latitude,
      longitude: snapshot.longitude,
      battery: snapshot.battery,
      trigger_method: snapshot.trigger_method,
      escalation_hop: '1',
      snapshot_url: `https://api.shoudeng.app/v1/sos/${snapshot.event_id}/snapshot`
    }
  };

  const result = await provider.send(note, deviceToken);
  return result;
}

6.4 服务端 SOS 处理流程

// Cloud Function: onSOSTrigger
exports.onSOSTrigger = functions.https.onCall(async (data, context) => {
  const snapshot = data.snapshot;
  const protectedPersonId = snapshot.sosEvent.protectedPersonId;

  // 1. 存入 Firestore
  await db.collection('sos_events').doc(snapshot.sosEvent.id).set(snapshot);

  // 2. 查询所有守护者
  const guardians = await getGuardiansForPerson(protectedPersonId);

  // 3. Hop 1: 找到值班守护者，发 Critical Alert
  const onDuty = guardians.find(g => g.isOnDuty) || guardians[0];
  if (onDuty) {
    const token = await getAPNsToken(onDuty.id);
    await sendCriticalSOSAlert(token, snapshot);
  }

  // 4. 启动升级定时器
  // Hop 2: 3分钟后如无人应答 → 通知所有守护者 + SMS
  await scheduleEscalation(snapshot.sosEvent.id, 'hop2', 180);

  // Hop 3: 5分钟后如仍无人应答 → VoIP 语音外呼
  await scheduleEscalation(snapshot.sosEvent.id, 'hop3', 300);

  return { success: true, eventId: snapshot.sosEvent.id };
});

// AppCoordinator 中配置 EscalationEngine 回调
func setupEscalationCallbacks() {
    escalationEngine.onSendNotification = { request in
        Task {
            switch request.priority {
            case .critical:
                // 通过服务端发 Critical Alert (直连 APNs)
                try await self.apiClient.post(
                    "/v1/push/critical", body: request)
            case .high:
                // 通过 FCM 发普通高优先级推送
                try await self.apiClient.post(
                    "/v1/push/send", body: request)
            case .normal:
                // 通过 FCM 发普通推送
                try await self.apiClient.post(
                    "/v1/push/send", body: request)
            }
        }
    }

    escalationEngine.onInitiateVoiceCall = { guardianId, sosId in
        Task {
            // 服务端通过 Twilio 发起语音外呼
            // 同时发 VoIP push 唤醒守护者 App
            try await self.apiClient.post(
                "/v1/sos/\(sosId)/voice-call",
                body: ["guardian_id": guardianId])
        }
    }

    escalationEngine.onEscalationFrozen = { session, guardianId in
        // 更新 Firestore SOS 文档
        Task {
            try await self.apiClient.post(
                "/v1/sos/\(session.sosEvent.id)/freeze",
                body: ["guardian_id": guardianId])
        }
    }
}

11. 离线与降级策略

11.1 被守护者离线

场景策略
SOS 时无网络 本地存储 SOSSnapshot + 加入 OfflineQueue。
恢复网络后自动上报 (已有 OfflineQueue 机制)
GPS 无信号 使用最后已知位置 + WiFi/基站定位。
Location.accuracy 标注精度供守护者参考
手机关机/没电 服务端检测心跳中断 → 自动升级为 "失联" 状态 → 通知守护者

11.2 守护者离线

场景策略
App 未安装 SMS 兜底 (Hop 2)
手机关机 APNs 会暂存推送，开机后送达。
同时 SMS + 语音外呼确保备用通道
网络差 Notification Service Extension 预拉取 snapshot 并缓存。
App 打开后优先读缓存

11.3 服务端降级

场景策略
Firebase 宕机 直连 APNs 不经过 FCM，Critical Alert 仍可送达。
Twilio SMS/Voice 独立于 Firebase
API 超时 客户端本地运行 EscalationEngine，
以 P2P 方式发送通知 (需要守护者设备的 push token 本地缓存)

12. 安全与隐私

措施说明
传输加密所有 API 通信使用 TLS 1.3。APNs 原生 TLS

# 守灯 × iPhone Duo（折叠屏）方案

2026-10-31 · 依据：Apple 官方文档、HIG「Designing for iPhone Duo」、Tech Talks、本机 Xcode 27.1 SDK 与 iPhone Duo 模拟器；代码基于 `release/1.0-integration`。

---

## 一、iPhone Duo 是什么（已确认）

| 项目 | 内容 |
|---|---|
| 上市 | 2026-09-09 发布，10-23 起发售，需 iOS 27.1 |
| 屏幕 | **外屏** 5.4″，466×678 pt；**内屏** 7.6″ 可折叠，669×951 pt（原生横向 951×669）。两块屏不会同时显示普通 App，折叠/展开时内容在两块屏之间移动 |
| 姿态 | 合上（外屏）、完全展开、半折（书本 / 桌面「笔记本」/ 帐篷） |
| 尺寸等级 | 外屏竖：compact 宽；内屏：**regular / regular**（任何方向）；内屏支持两个 App 分屏 |
| 系统栏 | 外屏和内屏横向时，**标签栏、工具栏、状态栏移到屏幕侧边，竖向排列**；Dynamic Island 也在侧边 |
| 生物识别 | **没有 Face ID**，只有侧键 Touch ID |
| 新 API（iOS 27.1） | 折痕区域 `reservedRegions(kind: .division)`；姿态 `onHingeChange`（只用于效果，不可用于布局）；`ArrangementView`（分栏 / 上下叠放）；侧边栏 `toolbarVerticalEdge` 等 |
| 不做适配会怎样 | 用 iOS 26 及更早 SDK 编译：内屏中间显示一个普通 iPhone 大小的窗口，四周留黑边。用 **iOS 27.1 SDK** 编译：铺满全屏、系统栏变竖向，所以**升级 SDK 前必须先检查布局** |
| App Store | Duo 截图（1398×2034、2007×2853）目前可选，提供后获「为 iPhone Duo 优化」标识；**2027 年 4 月起必需** |

## 二、守灯现在在 Duo 上的情况

**好消息：** 代码里早已有「Duo」双栏设计（`DuoAdaptiveTabContainer`，以及 10 个页面的 `duoPaneLayout`），外屏走手机布局、内屏走双栏，方向和 Apple 的思路一致。Info.plist 支持所有方向，没有 `UIRequiresFullScreen`。在 iPhone Duo 模拟器（外屏）上实测：显示正常，状态栏在右侧竖排。

**需要改的问题：**

| # | 问题 | 影响 | 位置 |
|---|---|---|---|
| 1 | 双栏左栏宽度写死 **445 pt** | 内屏竖拿（669 宽）时折痕在约 334 pt，**正好穿过左栏中间**；横拿（951 宽）时折痕在 475 pt，右栏前 30 pt 压在折痕上 | 10 个页面的 `.frame(width: 445)` |
| 2 | 自制的竖向标签栏 `VerticalTabRail` | Apple 明确说自定义栏不会适配；系统标签栏在外屏和内屏横向时会自动变竖向，自制的反而错位 | `DuoAdaptiveTabContainer` |
| 3 | 只看 `horizontalSizeClass == .regular` | 内屏分屏时只剩一半宽度，也会变成 compact，需要手机布局能在约 475 pt 宽度下用 | 全局 |
| 4 | `UIScreen.main.bounds` | Duo 有两块屏，这个值不可靠，且即将废弃 | `DisguiseCalculatorView.swift:43` |
| 5 | 登录、引导页宽度写死 445 | 分屏时太宽 | `LoginView.swift:181`、`OnboardingView.swift:85` |
| 6 | 没有双栏的关键页面 | 成员详情、守护者响应 SOS、SOS 倒计时、医疗卡、出行守护、领事馆 —— 在内屏上是拉宽的手机界面 | 各页面 |
| 7 | 体验模式功能列表写死「Face ID」 | Duo 只有 Touch ID（解锁提示本身已按设备显示 Face ID / Touch ID，没问题） | `explore.feature.biometrics` |
| 8 | 实时活动 / 小组件 | Duo 外屏的侧边 Dynamic Island 需要 compact、minimal、expanded、锁屏四种布局都齐全；StandBy 两块屏都能用 | `ShouDengWidgets/` |

## 三、设计原则（来自 HIG，结合守灯）

1. **只设计两种布局：** 外屏用手机布局，内屏多显示一层（列表 + 详情）。不为每种姿态单独设计。
2. **折痕上不放东西：** 双栏按折痕 50 / 50 分开；按钮、尤其 **SOS 按钮绝不放在折痕上**。
3. **折叠 / 展开不丢状态：** 正在看的人、聊天输入框里的字、SOS 倒计时都要保持（系统会保留同一个窗口，我们不能在尺寸变化时重置状态）。
4. **用系统的栏：** 标签栏、工具栏交给系统（会自动变侧边竖向），每个标签和按钮都要有「文字 + 图标」。
5. **SOS 一直一触可达：** 任何屏幕、任何姿态、分屏时都在同一个位置附近。
6. **不靠折叠动作触发任何紧急操作**（Apple 也明确：铰链角度只用于效果）。

## 四、每个页面怎么设计

| 页面 | 外屏（合上） | 内屏（展开） | 半折（桌面模式） |
|---|---|---|---|
| **守护者首页** | 现有手机布局 | 左：家人列表（状态卡）；右：选中家人的详情（地图、电量、最近动态、联系按钮）。替代现在的「左概览 + 右成员面板」 | 上半：所有家人地图；下半：家人列表与联系按钮 |
| **被守护者首页** | 现有布局；SOS 在右下 | 左：我的状态、报平安、到家了；右：守护我的人 + 家庭圈最新消息 | 上半：地图与当前位置；下半：大号「报平安 / SOS」 |
| **家庭圈** | 聊天列表 + 输入框 | 左：消息列表；右：选中消息的回复串，或家人位置面板 | 上半：消息；下半：输入框与键盘（像笔记本打字） |
| **守护者响应 SOS**（最重要） | 现有全屏警报 | 左：实时地图 + 位置轨迹；右：倒计时、一键「我来处理」、拨打对方 / 当地急救、医疗卡 | **上半：实时地图；下半：处理按钮**（`ArrangementView` 上下叠放）。手机立在桌上即可边看边打电话 |
| **被守护者 SOS 倒计时** | 全屏倒计时 + 取消 | 居中卡片，**不跨折痕**；取消按钮在右半屏中下部 | 下半屏显示取消按钮，上半屏显示倒计时 |
| **成员详情** | 现有布局 | 左：地图 + 状态；右：时间线 + 操作 | — |
| **记录** | 现有布局 | 左：事件列表；右：选中事件详情（已有雏形） | — |
| **设置** | 现有布局 | 左：分组列表；右：分组内容（标准设置样式） | — |
| **出行守护** | 现有布局 | 左：路线地图；右：出发前清单、卫星状态、Apple 地图按钮 | 上：地图；下：清单 |
| **医疗卡** | 现有布局 | 两栏：基本信息 / 过敏与用药，方便急救人员快速看 | — |
| **登录 / 引导** | 现有布局 | 已有 50 / 50 双栏（正好避开折痕）；去掉写死的 445 宽度 | — |
| **体验模式** | 提示卡在底部 | 提示卡放在右半屏，不遮挡左半屏真实界面 | — |

## 五、可以新增的功能（Duo 带来的机会）

| 功能 | 说明 | 价值 | 难度 |
|---|---|---|---|
| **SOS 桌面模式** | 守护者收到求助时，把手机半折立在桌上：上半屏实时地图，下半屏「我来处理 / 打电话 / 打急救」。通话时不用一直拿着手机 | ★★★ 守护者最需要的场景 | 中 |
| **长辈大屏模式** | 被守护的长辈展开手机，就自动用大字号、大按钮的版本（报平安、到家了、SOS 三个大按钮） | ★★★ 主要用户是老人 | 低 |
| **地图 + 聊天并排** | 内屏一边看家人位置，一边在家庭圈里沟通（例如接送、出行） | ★★ | 低（用列表 + 详情即可） |
| **视频通话桌面模式** | 半折立起，上半屏视频，下半屏控制（若将来加入视频通话） | ★★ | 高（需要视频功能本身） |
| **StandBy 家人状态** | 夜里充电立着时，两块屏都可显示「全家平安 / 谁还没报平安」小组件 | ★★ 守护者睡前看一眼 | 中（大尺寸小组件） |
| **侧边 Dynamic Island** | SOS、回家倒计时的实时活动在外屏侧边岛上清楚可读 | ★★ | 低（补齐四种布局） |
| **分屏配合** | 守灯 + 电话 / 地图 / 信息分屏：边看位置边打电话 | ★★ | 低（保证约 475 pt 宽度下布局正常） |

> 不建议做：根据铰链角度触发任何操作（如「合上手机取消 SOS」）——Apple 不保证更新频率，也容易误触。

## 六、技术方案

1. **SDK：** 用 Xcode 27.1 / iOS 27.1 SDK 编译；最低系统保持 iOS 17，新 API 用 `if #available(iOS 27.1, *)` 包起来。
2. **标签栏：** 去掉自制 `VerticalTabRail`，用系统 `TabView`（`.tabViewStyle(.sidebarAdaptable)`）；所有标签、工具栏按钮都提供文字 + SF Symbol；SOS 继续作为固定的底部附件（家庭圈已改为由页面自己放在输入框上方）。
3. **双栏：** 「列表 → 详情」类页面改用 `NavigationSplitView`（外屏自动收成单栏，内屏自动 50 / 50 避开折痕）；其他双栏页面去掉 445 写死宽度，iOS 27.1 上用 `reservedRegions(kind: .division)` 让分隔线对齐折痕，旧系统按 50 / 50。
4. **桌面模式：** SOS 响应、被守护者首页、出行守护用 `ArrangementView` 的上下叠放样式（iOS 27.1+），旧系统和普通 iPhone 自动退回现有布局。
5. **状态保持：** 检查所有用 `sizeClass` 切换布局的页面，切换时不能重建 `@State`（输入框文字、选中的家人、倒计时）；必要时把状态提到上层。
6. **其他：** `UIScreen.main` 改为按视图宽度；登录 / 引导去掉固定宽度；体验模式的「Face ID」改为按 `biometryType` 显示；补齐实时活动四种布局与大尺寸小组件。
7. **测试：** iPhone Duo 模拟器（`com.apple.CoreSimulator.SimDeviceType.iPhone-Duo`，iOS 27.1）——合上、展开竖横、半折、内屏分屏；五种语言（法语、日语较长）；大字号；用 Xcode Device Hub 切换姿态。截图测试加入 Duo 两种尺寸。

## 七、分阶段

| 阶段 | 内容 | 工作量 |
|---|---|---|
| **A. 能正确显示（升级 SDK 前必须完成）** | 去掉 445 写死宽度、双栏对齐折痕；系统标签栏替换自制竖栏；`UIScreen.main`、固定宽度、Face ID 文案；折叠时状态不丢；分屏宽度下布局正常；Duo 模拟器全页面过一遍 | 约 1–1.5 周 |
| **B. 用好大屏** | 守护者首页、家庭圈、成员详情、记录、设置改为「列表 + 详情」；SOS 响应双栏；长辈大屏模式 | 约 1.5–2 周 |
| **C. 桌面模式与系统界面** | SOS 桌面模式、出行守护桌面模式；实时活动四种布局、StandBy 大小组件；App Store Duo 截图 | 约 1–1.5 周 |

**截止时间：** App Store 2027 年 4 月起要求 Duo 截图；建议 A 阶段在下一次以 iOS 27.1 SDK 提交前完成，B、C 在 2027 年 3 月前完成。

## 八、需要你决定

1. 是否在下一个版本就用 iOS 27.1 SDK 编译（决定 A 阶段是否马上做）。
2. 「长辈大屏模式」是否展开就自动启用，还是在设置里开关。
3. 「SOS 桌面模式」是否作为 Duo 的主打功能（影响 C 阶段优先级和 App Store 宣传图）。
